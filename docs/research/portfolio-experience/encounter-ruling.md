## Failures found and corrected during the trial

1. **Scrollbar-induced target movement:** first acquisition narrowed a target
   from 167.96875 to 165.28125 px and shifted its neighbors. Reserved scroll space
   fixed this. A subsequent before/after comparison of all six document-relative
   x/y/width/height records was exactly equal, with 102 px heights. Changing status
   text was moved below the scan controls.
2. **Insufficiently visible qualification:** the initial prototype put the Kandev
   text behind disclosure. It now displays the complete limitation in normal flow.
3. **Resume chronology loss:** releasing R initially reset the local window.
   Resume now retains its prior window and labels it as retained while scanning.
4. **Unknown URL retained old window:** the first same-document unknown legacy
   trial cleared R/S but left the old window. Explicit invalid intent now clears
   it; readback showed P/R/S/window all empty.
5. **200% text overflow:** the timeline select and native test input extended to
   483 and 408 px respectively in a 375 px content viewport. Bounded control
   widths fixed this; the repeated enlarged-text check was 375/375 px.
6. **Wrong focus origin under dwell acquisition:** the slow pointer sweep acquired
   Digi 003 while keyboard focus remained C24; the initial return source was C24.
   The origin now binds to the acquired subject, and the repeated real sweep plus
   native-page return restored both Digi 003 and its control focus.
7. **Relationship panel could follow P during held reading:** inspection found
   this could replace frame links while R stayed fixed. Final relationship focus
   follows R, then S, then P when no reference is held; unchanged focus retains
   the existing link elements. The repeated C24-hold/Rack-preview check retained
   C24's absence text. Acquiring Digi yielded exactly its one semantic edge/line.

These are prototype revisions, not shipped production repairs. The final hash
identifies the revision after the fixes; the four-way comparison preceded the
last source-focus/held-relationship corrections. Their affected behaviors were
re-exercised after those corrections. No broader production-quality claim follows.

## Accepted implementation ruling

Erik's **Go A + 2** accepts this implementable direction:

1. Separate preview P, acquired reading R and explicit pin S within the existing
   HXO ownership boundary. Hover/focus identifies immediately; explicit Read
   acquires. Do not carry the 450 ms auto-acquisition trial into implementation.
2. Hold R and its links until another deliberate acquisition or Resume scanning.
   Pin/Unpin/Return to pinned are named controls with the semantics above. Escape
   dismisses preview; it does not silently unpin. Preserve input/dialog behavior.
3. Keep a whole-career overview and update a separate chronological neighborhood
   on acquisition. Use recorded dates, explicit undated access and deterministic
   date/ID order; expose every dense member through semantic links. Retain the
   window on Resume. No camera transform, automatic zoom or queued tween is
   justified by this trial. Exact production density/layout remains a focused
   implementation review, not a license to reintroduce unreachable members.
4. Keep held relationship text/links with R, using only its approved incident
   edges. Label previews separately. Preserve the distinction between time,
   practice examples and verified project relationships.
5. Carry public R separately from S through native navigation. Explicit URL intent
   wins over unrelated session restoration; invalid/stale/denied state leaves
   ordinary navigation usable. Resume restores a validated originating control;
   direct entry uses Explore around this project without inventing prior history.
6. Preserve ordinary static links, full qualifications, equivalent deliberate
   input and persistent Pause. Downstream production checks must cover real
   rendering/hydration, touch, focus, motion, claims and return behavior in context.
